# LifeTimeline: переписать сцену как step-машину

## Диагноз (по коду)

- `LifeTimeline.tsx:391-408` — все 4 карточки смонтированы постоянно в одной grid-ячейке `col-start-1 row-start-1`; скрытие только через inline `opacity: 0`, узел остаётся в DOM с `shadow-hard` и `backdrop-blur-md`. Отсюда наложение кризиса на соседнюю карточку.
- `storyColumnClass:205-209` — главы 1 и 2 получают одну и ту же колонку `md:col-start-1`, то есть два бокса стоят буквально в одном месте.
- На карточке (`:396`) нет ни одного `transition-*` класса: анимация целиком зависит от частоты `syncChapter` (`:282-317`). Крупный дельта-скролл между кадрами даёт разрыв вместо перехода.
- `cardMotion:331-345` — при `0.15 ≤ trackProgress ≤ 0.8` возвращается константа `{opacity:1, translateY:0}`. На секцию `h-[190vh]` (`:420`) это ≈124vh полностью статичной прокрутки на главу — источник ощущения зависания.

## Целевая архитектура компонента

Заменить scroll-progress-модель на детерминированную step-машину.

### Состояние

```text
index: 0..3                  // активная глава
phase: "idle" | "out" | "in" // фаза перехода
lockUntil: number            // ts окончания блокировки шага
```

### Правила перехода

1. `step(dir)` допускается только при `phase === "idle"` и `now >= lockUntil`.
2. `step(+1)` на `index === 3` и `step(-1)` на `index === 0` не перехватываются — событие уходит странице, сцена отпускает скролл.
3. Последовательность шага: `phase="out"` → по завершении меняется `index` → `phase="in"` → `idle`.
4. Один жест = один шаг. Импульс тачпада гасится: после шага ставится `lockUntil = now + 520ms`, а повторный шаг разрешается только после `wheel`-паузы ≥ 90ms (детектор конца жеста), поэтому инерция не перескакивает через кризис.

### Тайминги (быстро, без зависаний)

- выход карточки: 180ms, `translateY(-28px)`, opacity 1→0, `ease-out`;
- смена содержимого: 0ms (по `transitionend` фазы out);
- вход карточки: 220ms, `translateY(28px)→0`, opacity 0→1, `ease-out`;
- полный шаг ≈ 400ms; блокировка 520ms;
- зоны и шкала: 320ms вместо текущих 1000–1500ms;
- `prefers-reduced-motion`: без transform, opacity 120ms, та же step-логика.

### Ввод

- `wheel`: порог `|deltaY| ≥ 12`, нормализация `deltaMode`, `preventDefault` только когда сцена закреплена и шаг возможен внутри диапазона.
- `touchstart/touchmove/touchend`: вертикальный свайп ≥ 40px = один шаг.
- `keydown`: `ArrowDown/ArrowUp/PageDown/PageUp/Space` = один шаг.
- Slider: `onValueChange` вызывает ту же `step`-последовательность до целевого индекса без промежуточных пауз.

### Рендер

- Рендерить ровно один экземпляр карточки из `chapters[index]`, а не `chapters.map`. Два узла одновременно не существуют ни в одной фазе — перекрытие структурно невозможно.
- Колонка берётся как `storyColumnClass(chapters[index].id)` на единственном узле. Для главы 2 задать отдельную позицию, чтобы кризис не занимал колонку главы 1.
- Добавить на карточку `transition-[opacity,transform]` с указанными выше длительностями, управляемыми фазой, а не прогрессом.
- Интервал и название активного состояния вынести в фиксированный слот на шкале, вне анимируемой карточки.

### Удалить

- 4 пустые секции `h-[190vh]` (`:413-423`), `chapterRefs`, `trackProgress`, `cardMotion`, `syncChapter`, `moveToChapter`.
- Сцену держать закреплённой через один контейнер фиксированной высоты (`h-[calc(100vh-4rem)]` + короткий трек ~`120vh` для входа/выхода всей сцены), без per-chapter треков.

## Проверка (Playwright, 390/768/974/1440 px)

- один `wheel` c `deltaY=120` = ровно +1 индекс; серия из 6 событий за 100ms = +1, не +6;
- при каждом промежуточном кадре в DOM ровно один `[data-story-card]`;
- проход 0→3 и обратно 3→0 через все четыре состояния, включая кризис;
- на `index=3` скролл вниз продолжает страницу к блоку персон, на `index=0` вверх — к предыдущей секции;
- Slider даёт те же четыре состояния;
- `overflow-x = 0`, page errors отсутствуют.
