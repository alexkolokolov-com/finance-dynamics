# Страница мероприятия

Страница мероприятия — это не статья и не продуктовый лендинг. Её задача: за один экран объяснить тему, дату и дать кнопку. Образец — `/event`.

## Структура (4–6 блоков, не больше)
1. Первый экран.
2. О мероприятии: заголовок + одна фраза (+ картинка).
3. Программа: 3–6 тезисов или 3–4 части по 2–3 пункта. Без таймингов у вебинара, без разворачивания.
4. Опционально: подарок / ведущий — компактно.
5. Регистрация: дата одной строкой, заголовок, одна кнопка.

Меню страницы (`pageNav`) — максимум 3 пункта: «О …», «Программа», «Регистрация» (cta).

## Первый экран
- Телефон, порядок: фото → плашки с датой/временем и форматом поверх фото → H1 → кнопка. Кнопка видна без прокрутки на 320 и 390 px.
- Компьютер: текст слева (7/12), фото справа (5/12), плашки над заголовком.
- H1 — тема мероприятия, а не лозунг. Формат и ведущий — подписью/плашкой.
- Под H1 максимум одна короткая фраза. Ни одной кнопки кроме основной.
- Картинка — отдельный `<img>`, никогда не фон под текстом.

## Тексты
- Только формулировки пользователя. Сокращать можно, перефразировать — нет без согласования.
- В абзаце ≤ 2 строк на компьютере, в блоке ≤ 1 абзаца.
- Одна мысль — один раз на странице. Цитата не повторяет цифры из карточек.
- Нет серого мелкого текста, служебных приписок («пробная форма», «пока не открыто»), английских вставок, если есть русское слово.
- Нет надзаголовков-счётчиков и капс-подписей. `nbsp()` во всех русских текстах.

## Иерархия
- Один H1. У каждого блока один H2. H3 только внутри программы.
- Одинаковый текст кнопки на всей странице («Зарегистрироваться»), все кнопки открывают одну форму.

## Чек-лист перед сдачей
- [ ] Блоков ≤ 6, меню ≤ 3 пунктов.
- [ ] 320/390/1280: нет горизонтальной прокрутки, кнопка на первом экране телефона.
- [ ] Нет `text-muted-foreground`-абзацев и приписок мелким шрифтом.
- [ ] Нет повторов мыслей и цифр между блоками.
- [ ] Дата/время/цена берутся из файла данных и покрыты тестом.
- [ ] Общий SiteHeader + Footer, маршрут в `src/App.tsx`.
